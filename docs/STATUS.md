# حالة المشروع — BROCCOLI

آخر تحديث: 2026‑11‑12 (الجلسة الأولى)

## ما شُغِّل فعلياً في هذه الجلسة

| الفحص | النتيجة |
|---|---|
| `npm run test` — محاكاة | 19/19 ناجح |
| `npm run lint` — TypeScript | بلا أخطاء |
| `npm run build` | ناجح (app.js ≈ 53KB) |
| `npm run test:e2e` — Chrome، 844×390 أفقي، لمس، UA آيفون + سطح مكتب بالفأرة | 23/23 ناجح، بلا أخطاء console، زمن الإطار ≈16.7ms |

**لم يُختبر:** Safari حقيقي على آيفون (لا يتوفر WebKit في بيئة البناء). الاختبار تم على Chrome بمحاكاة مقاس ولمس الآيفون. كذلك لم يُجرَّب `npm install` على Windows نفسه.

## P0 — مكتمل
- المجلد كان فارغاً؛ أُنشئ monorepo TypeScript.
- **انحراف عن المواصفات:** Phaser و Vite و Vitest غير مستخدمة لأن بيئة البناء لا تسمح بتنزيل الحزم. البديل: Canvas 2D + esbuild + `node:test`. المحاكاة معزولة تماماً عن الرسم، فاستبدال طبقة الرسم بـ Phaser لاحقاً لا يمس القواعد.

### ملاحظات صريحة على P1
- **الفن مؤقت بمستوى جيد:** مرسوم بالكود (canvas)، وليس أطلس sprites نهائياً. الجنود بإطارين واتجاهين (يمين/يسار) لا 4–8 اتجاهات.
- **لا موسيقى** بعد؛ مؤثرات فقط.
- **لا اختيار بطل** في P1 (الأبطال من P2)، لذلك لا يظهر زر له.
- التوازن أولي ولم يُضبط بلعب بشري. Normal قد يكون صعباً على المبتدئ.
- لا حفظ للمباراة، لا zoom/pan (الخريطة كلها ظاهرة).

## المتبقي

**P2:** 4 أبطال × 4 مهارات + طاقة، خريطتان إضافيتان، مستويات AI ‏Beginner/Expert، 10 دروس تفاعلية، موسيقى، حفظ Solo، خيار تأكيد الإرسال، Snake/طابور أوامر، اختبار على آيفون حقيقي.
**P3:** خادم authoritative (المواصفات: Colyseus)، غرف برمز، 1v1 ثم 2v2، إعادة اتصال. المحاكاة جاهزة لتعمل على الخادم كما هي.
**P4:** 24 بطلاً، 12+ خريطة، Domination و King of the Bloom، حملة، ملف شخصي، إعادات، متفرجون.
**P5:** PWA، Capacitor، أداء ووصولية، تدقيق الأصول.
